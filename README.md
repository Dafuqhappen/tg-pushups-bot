# TG push-ups bot

Telegram-бот для чата с ежедневным фитнес-челленджем. Участники присылают в чат
видео-кружки (video notes) с подходами — подтягивания, отжимания, приседания,
планка. Бот считает их, ведёт стрики, каждое утро публикует сводку за прошедший
день и в течение дня подкидывает цитаты-пинки.

Работает в проде с апреля 2026 в чате на ~15 человек.

```
📅 итоги 23.06.2026

✅ челлендж прошли: Алиса, Борис, Виктор
🫵 100% — real push ups bro.

стрики:
• Алиса — 20 🔥 (рекордный стрик 35, всего 412)
• Борис — 20 🔥 (рекордный стрик 23, всего 287)
• Виктор — 1 🔥 (рекордный стрик 14, всего 96)

не дотянули:
• Галина — 3/4   🔥 75% — один кружок до нормы, надо добить.

• Дмитрий — 1/4   🌱 25% нормы — уже что-то. Завтра соберись.
```

## Возможности

- **Автоподсчёт.** Слушает `video_note` в заданном чате, пишет каждый в SQLite.
  Пересланные кружки тоже считаются.
- **Логический день вместо календарного.** День идёт от `DAY_CUTOFF_HOUR` до
  того же часа следующих суток. Иначе норма, добитая в час ночи, попадала бы в
  «завтра» и рвала стрик — см. [Логический день](#логический-день).
- **Стрики с амнистией.** Один пропущенный день в календарный месяц прощается,
  второй обнуляет стрик — см. [Правила стрика](#правила-стрика).
- **Три рассылки в день:** сводка в `SUMMARY_HOUR` (09:00) + цитаты в 15:00 и
  21:00. Цитаты не повторяются, пока не отыграет весь пул из 200 штук;
  использованные хранятся в БД, так что цикл переживает рестарты.
- **Тихий режим.** Участник может попросить не показывать его в публичных
  подсчётах — `EXCLUDED_USER_IDS` убирает его из сводки и `/top`, при этом
  кружки продолжают писаться, а личный `/stats` работает.
- **Устойчивость к сети.** Плановые отправки ретраятся с экспоненциальным
  бэкоффом (до 30 попыток, потолок 60 с между ними) — см.
  [Живучесть](#живучесть-в-недружелюбной-сети).

## Стек

| | |
|---|---|
| Язык | Python 3.11+ (в проде 3.14) |
| Telegram | `python-telegram-bot[job-queue]` 22.x — long polling + APScheduler |
| Хранилище | SQLite через `sqlite3` из стандартной библиотеки |
| Импорт истории | `Telethon` — разовый бэкфилл под user-аккаунтом |
| Деплой | systemd user-unit на VPS, без root |

Внешних сервисов, брокеров и ORM нет — бот держится на одном процессе и одном
файле БД.

## Быстрый старт

```bash
git clone https://github.com/Dafuqhappen/tg-pushups-bot.git
cd tg-pushups-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env      # заполнить BOT_TOKEN и CHAT_ID
.venv/bin/python bot.py
```

Что нужно со стороны Telegram:

1. Создать бота у [@BotFather](https://t.me/BotFather), забрать токен.
2. Выключить privacy mode: `/setprivacy` → `Disable`. Без этого бот не видит
   обычные сообщения в группе.
3. Добавить бота в чат, написать туда что-нибудь и взять `chat.id` из
   `https://api.telegram.org/bot<TOKEN>/getUpdates` — у супергрупп он выглядит
   как `-100…`.

## Конфигурация

Всё через `.env` (см. `.env.example`).

| Ключ | Дефолт | Описание |
|------|--------|----------|
| `BOT_TOKEN` | — **обязателен** | Токен от @BotFather |
| `CHAT_ID` | — **обязателен** | ID чата, вида `-100…` |
| `TIMEZONE` | `Europe/Moscow` | Пояс для расписаний и границ дня |
| `DAILY_GOAL` | `4` | Сколько кружков = норма за день |
| `DAY_CUTOFF_HOUR` | `6` | Час, в который кончается логический день |
| `SUMMARY_HOUR` | `9` | Час публикации сводки |
| `SEASON_START` | `2026-06-01` | С какой даты считаются стрики |
| `EXCLUDED_USER_IDS` | пусто | ID через запятую — «тихий режим» |
| `DB_PATH` | `data/pushups.db` | Путь к файлу SQLite |
| `TG_PROXY_URL` | пусто | Прокси до Telegram, если провайдер его режет |
| `TG_API_ID` / `TG_API_HASH` / `TG_PHONE` | пусто | Нужны только для бэкфилла |
| `BACKFILL_SINCE` | `2026-04-01` | С какой даты тянуть историю |

Секретов в репозитории нет: `.env`, `*.session` и `*.db` в `.gitignore` и
никогда не попадали в историю коммитов.

| Команда | Что делает |
|---|---|
| `/stats` | Твоя статистика: сегодня, всего, текущий и рекордный стрик, статус месячной амнистии |
| `/top` | Таблица участников по стрикам |

## Как это устроено

### Логический день

Наивный подход — считать кружки по календарной дате — ломается на живых людях:
кто-то добивает норму в 00:30, кто-то тренируется в 07:00 перед работой. И то,
и другое человек считает «сегодняшней» тренировкой, а `date()` — нет.

Поэтому день сдвинут: всё, что отправлено до `DAY_CUTOFF_HOUR`, относится к
предыдущему дню.

```python
def to_local_day(dt: datetime) -> date:
    return (dt.astimezone(TIMEZONE) - timedelta(hours=DAY_CUTOFF_HOUR)).date()
```

Значение подбиралось по жалобам из чата: начинали с `9` (ломало тех, кто
тренируется утром до работы), пробовали `3` (ломало тех, кто добивает норму
ночью), остановились на `6` — оно закрывает оба сценария.

`SUMMARY_HOUR` намеренно отделён от `DAY_CUTOFF_HOUR`: день закрывается в 06:00,
а сводка выходит в 09:00, когда её кто-то прочитает.

### Правила стрика

- Сезон каждого участника начинается с его **первого дня с выполненной нормой**.
  Дни до этого игнорируются — иначе человек, присоединившийся к челленджу 10-го
  числа, стартовал бы с уже потраченной амнистией.
- Норма выполнена → `current_streak += 1`.
- Норма не выполнена, **первый** раз в этом календарном месяце → стрик выживает
  (амнистия), но не растёт.
- Норма не выполнена **второй** раз за месяц → `current_streak = 0`. Амнистия
  восстанавливается только со следующего месяца.
- `best_streak` — рекорд за всё время, только растёт. Пересчёты его не понижают.

Состояние амнистии хранится в `streaks.skip_used_month` (`YYYY-MM`), так что
сброс на границе месяца происходит сам собой, без крона.

### Живучесть в недружелюбной сети

Изначально бот жил на VPS в РФ, где провайдер окнами по 10–40 минут резал TLS до
`api.telegram.org`. Диагностика оказалась неочевидной: уже установленное
long-poll соединение продолжало работать, поэтому бот **принимал** кружки и
выглядел живым — а плановые `send_message`, которым нужен свежий TCP, молча
умирали по таймауту, и сводки терялись.

Что из этого осталось в коде:

- `_send_with_retry` — экспоненциальный бэкофф с потолком 60 с, до 30 попыток
  (~36 минут терпения). Ретраится только на `TimedOut` / `NetworkError`.
- Увеличенные таймауты `HTTPXRequest`; для long-poll отдельный инстанс с бо́льшим
  `read_timeout`, чем интервал опроса.
- Опциональный `TG_PROXY_URL`.
- `send_missed_summary.py` — досылка сводки, если плановая всё-таки не ушла.

Радикально проблему решил переезд на VPS за пределами РФ; механизмы выше
оставлены как страховка. Увеличивать `connect_timeout` смысла не было — во время
блокировки SYN-пакеты дропаются, и ожидание дольше просто делает каждую неудачу
медленнее.

### Импорт истории

Bot API не отдаёт сообщения, отправленные до того, как бота добавили в чат.
`backfill.py` дотягивает их через Telethon под user-аккаунтом.

```bash
.venv/bin/python backfill.py        # при первом запуске спросит код из Telegram
.venv/bin/python recount_streaks.py # пересчитать стрики по добавленным данным
```

> **Нюанс.** Telethon под user-аккаунтом возвращает `first_name` с точки зрения
> вызывающего — то есть **имена из твоей адресной книги**, а не те, что люди
> поставили себе сами. Поэтому `backfill.py` вызывает
> `db.upsert_user(..., update_first_name=False)` и не перезатирает имена уже
> известных участников.

## Структура

```
bot.py               точка входа: хендлеры + три ежедневные джобы
handlers.py          обработка video_note, команды /stats и /top
scheduler.py         сборка сводки + отправка с ретраями
db.py                SQLite: users, video_notes, streaks, used_quotes
config.py            чтение .env, логический день
quotes.py            пул цитат + выбор без повторов
backfill.py          разовый импорт истории через Telethon
```

Служебные скрипты (запускаются руками, не частью бота):

```
preview_summary.py     показать, как выглядела бы сводка за день, ничего не отправляя
recount_streaks.py     пересчитать стрики с нуля по данным в БД
migrate_cutoff.py      пересчитать local_date после смены DAY_CUTOFF_HOUR
send_missed_summary.py дослать сводку, если плановая не ушла
inspect_streak.py      диагностика: юзеры, стрики, кружки за последние дни
june_counts.py         диагностика: подневная разбивка по участнику за месяц
april_finale.py        итоги месяца с рейтингом и «интересными фактами»
```

## Деплой

Бот работает под обычным пользователем, без root — systemd user-unit.

```bash
loginctl enable-linger $USER   # чтобы юнит пережил logout и reboot
mkdir -p ~/.config/systemd/user
```

`~/.config/systemd/user/pushups-bot.service`:

```ini
[Unit]
Description=TG push-ups bot
After=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/tg-pushups-bot
ExecStart=%h/tg-pushups-bot/.venv/bin/python bot.py
Restart=on-failure
RestartSec=5

NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=%h/tg-pushups-bot
PrivateTmp=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
MemoryMax=256M

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now pushups-bot
journalctl --user -u pushups-bot -f
```

Потребление в проде — около 35 МБ RAM, так что хватает самого дешёвого VPS.
